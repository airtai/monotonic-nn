# monotonic-nn v0.4.0 — thin compatibility shim over `mononet`

**Status:** Approved for implementation
**Date:** 2026-07-13
**Owner:** Davor Runje
**Triggering event:** The monotonic-network construction from the ICML 2023
paper now has a maintained, multi-backend implementation in
[`mononet`](https://github.com/davorrunje/mononet) (PyTorch, JAX, Keras 3).
`mononet.legacy` reproduces this repo's original `MonoDense` API faithfully
(numerically verified against `monotonic-nn==0.3.5` goldens). Rather than
maintain two implementations, `monotonic-nn` becomes a thin compatibility shim
that re-exports `mononet.legacy`, so existing users' code keeps working while the
real implementation lives in one place.

## Goal

Re-implement `monotonic-nn` as a deprecated, thin compatibility layer that
depends on `mononet` and re-exports `mononet.legacy`. Existing imports
(`from airt.keras.layers import MonoDense`, `MonoDense.create_type_1/2`, the
module-level helpers) continue to resolve, now backed by mononet.

## Non-goals

- Preserving TensorFlow-Keras-2 / Python 3.9–3.10 support. Adopting mononet
  requires **Keras 3 and Python 3.11+** — this is an accepted breaking change.
- Keeping the nbdev notebook-driven build. The package is modernized to a plain
  hatchling `pyproject.toml`.
- Re-porting the experiments/training code into mononet (it stays here, as-is).

## Decisions (from brainstorming)

| Decision | Choice |
|---|---|
| Restructure approach | Modernize to a thin shim; drop nbdev. |
| Compatibility posture | Hard-deprecate; steer users to `mononet`. |
| Distribution(s) | `monotonic-nn` only (not `mono-dense-keras`). |
| `experiments.py` | Kept as-is; docs pages get notices linking to mononet benchmarks. |
| Version | `0.4.0` (breaking, within 0.x). |
| Docs | Rework off nbdev to plain mkdocs; notices on every page. |

## Design

### 1. Build modernization (drop nbdev)

Remove: `settings.ini`, `setup.py`, `airt/_modidx.py`, the `_pyproject.toml`
stub, `# AUTOGENERATED` headers, and nbdev configs (`nbs/_quarto.yml`,
`nbs/nbdev.yml`, `nbs/sidebar.yml`).

Add a hatchling `pyproject.toml`:

- `name = "monotonic-nn"`, `version = "0.4.0"`, `requires-python = ">=3.11"`
- `dependencies = ["mononet>=0.0.0a1", "tensorflow>=2.16"]`

Rationale for `tensorflow>=2.16`: TF 2.16+ **bundles Keras 3**, which
(a) supplies the Keras 3 that `mononet.legacy` requires, (b) makes Keras 3
default to the TensorFlow backend — closest to existing users' environment, and
(c) keeps `experiments.py` (which imports `tf.keras`) working unchanged. mononet
itself stays TF-free; only this shim pulls TensorFlow. The `>=0.0.0a1`
specifier lets pip resolve the mononet alpha (PEP 440 allows prereleases when
the specifier itself names one).

### 2. Shim code (hand-written)

The `airt/` package is no longer autogenerated:

- `airt/__init__.py` — `__version__ = "0.4.0"`; preserve the `extend_path`
  namespace behavior; `__all__ = []`.
- `airt/_components/mono_dense_layer.py` — re-export the original public surface
  from `mononet.legacy`:
  `MonoDense, create_type_1, create_type_2, get_saturated_activation,
  get_activation_functions, apply_activations, get_monotonicity_indicator,
  apply_monotonicity_indicator_to_kernel,
  replace_kernel_using_monotonicity_indicator`, with the original `__all__`.
- `airt/keras/layers/__init__.py` — `from mononet.legacy import MonoDense`
  (and `create_type_1`/`create_type_2`); `__all__ = ["MonoDense"]`. Drop the
  nbdev `dummy` scaffold.
- `airt/keras/experiments.py` — kept as-is.
- `airt/keras/__init__.py`, `airt/_components/__init__.py` — kept (adjusted to
  drop any `_modidx` reference).
- Remove `airt/_modidx.py`.

`MonoDense.create_type_1/2` come for free — `mononet.legacy.MonoDense` already
carries those classmethods. Existing user code resolves unchanged.

### 3. Deprecation UX

- A single `DeprecationWarning` emitted on import of `airt.keras.layers`:
  monotonic-nn is deprecated; it now wraps `mononet` — use `mononet` directly
  (with a link). `mononet.legacy`'s own construction-time warning (layer-level)
  still fires; the two messages are complementary, not duplicative.
- `README.md` top banner: deprecated; now backed by mononet; requires Keras 3 /
  Python 3.11+; pointer to mononet.
- CHANGELOG `0.4.0` entry.

### 4. Docs rework (plain mkdocs, off nbdev)

- Replace nbdev-mkdocs with plain **mkdocs-material + mkdocs-jupyter**, reusing
  the existing `mkdocs/` config where possible, so notebooks still render and the
  site still deploys to GitHub Pages.
- Deprecation banner on every page.
- Per-experiment notice linking to the corresponding mononet benchmark
  (`https://davorrunje.github.io/mononet/main/benchmarks/paper-reproduction/…`):
  - `AutoMPG.ipynb` → `auto-mpg.html`
  - `Blog.ipynb` → `blog-feedback.html`
  - `Compas.ipynb` → `compas.html`
  - `Heart.ipynb` → `heart-disease.html`
  - `Loan.ipynb` → `loan-defaulter.html`
- Index/landing page points to the mononet docs.
- Replace the `deploy.yaml` nbdev-mkdocs action with a standard
  `mkdocs gh-deploy` (or build + Pages) workflow.

> Caveat (noted, not blocking): mononet migrated *off* mkdocs-material to Sphinx
> because mkdocs-material's maintainer is winding down. This shim proceeds with
> mkdocs per the maintainer's choice; Sphinx is an alternative if reconsidered.

### 5. Tests + CI

- Drop `nbdev_test`. Add a small `tests/` suite (pytest):
  - `from airt.keras.layers import MonoDense` resolves and
    `MonoDense is mononet.legacy.MonoDense`.
  - `MonoDense.create_type_1` / `create_type_2` are reachable.
  - A small `MonoDense` forward pass runs under the default Keras backend.
  - The `airt.keras.layers` import `DeprecationWarning` fires.
- Rewrite `.github/workflows/test.yaml` to plain pytest (Python 3.11–3.13).
- Rewrite `.github/workflows/deploy.yaml` to the mkdocs deploy.

### 6. Release & delivery

- `pyproject.toml` version `0.4.0`; CHANGELOG `0.4.0` entry describing the pivot
  and the Keras 3 / Python 3.11+ requirement.
- Deliver as a PR to `airtai/monotonic-nn` (`davorrunje` has push access — no
  fork needed). Maintainer reviews, merges, and publishes to PyPI.

## Testing strategy

| Test | Verifies |
|---|---|
| `tests/test_reexport.py` | `airt.keras.layers.MonoDense is mononet.legacy.MonoDense`; helpers importable from `airt._components.mono_dense_layer` |
| `tests/test_builders.py` | `MonoDense.create_type_1/2` reachable and build a runnable model (upstream list/dict input convention) |
| `tests/test_deprecation.py` | importing `airt.keras.layers` emits `DeprecationWarning` |
| `tests/test_forward.py` | a small `MonoDense` forward pass runs under the default backend |

## Follow-ups (possible, not blocking this release)

- **Make `experiments.py` run under Keras 3.** It is kept as-is in v0.4.0 but was
  written for tf.keras (Keras 2); under TF 2.16+ `tf.keras` is Keras 3, so parts
  may not run unchanged. Audit and either fix for Keras 3 or gate behind an
  optional `monotonic-nn[experiments]` extra (with a "legacy, may require older
  TensorFlow" note) and add a smoke test. Low priority — the core layer API is
  unaffected, and the maintained benchmarks now live in the mononet docs.
